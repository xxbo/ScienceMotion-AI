# P1.1 Acceptance — Executable creative loop

Last updated: 2026-11-14

## Status and scope

**Planned gates; not yet accepted.** The reviewed baseline is `26f20bab6b56a6aa8774c80e5da25db84d00fefb`, with successful [CI #43463301921](https://github.com/xxbo/ScienceMotion-AI/actions/runs/43463301921). Existing tests and the Episode-based CPU-cache render do not satisfy these new creative-loop gates by themselves.

P1.1 must prove an extensible tool platform through a bounded local 2D creation/edit/render workflow. Trusted in-process plugins and local storage are sufficient. Third-party sandboxing, remote execution and a full autonomous visual critique agent remain later work.

## Initial executable tool set (proposed)

Names below are planned interfaces, not current API availability. Equivalent names/grouping are acceptable if the behaviors and typed contracts are preserved; the target is roughly 10–12 tools, not a quota.

| Proposed tool | Required behavior |
| --- | --- |
| `project.create` | Create a valid empty project with initial revision and render profile |
| `project.scene.create` | Add a scene and its placement in a sequence through revisioned operations |
| `graphics.2d.text.create` | Create data-driven text with explicit typography/layout properties |
| `graphics.2d.shape.create` | Create reusable shapes without a topic-specific component |
| `project.node.transform.set` | Change position/rotation/scale with revision-conflict checks |
| `animation.keyframes.set` | Add/update a track with explicitly supported interpolation and timing |
| `assets.import` | Store local input bytes, validate provenance/type and link a project asset |
| `project.snapshot.save` | Persist immutable project state and protect referenced artifact dependencies |
| `project.snapshot.restore` | Restore project data and verify its asset dependencies |
| `render.preview` | Render a frame or short shot from a snapshot and return Artifact references |
| `render.video` | Render a short sequence and return output plus render-evidence references |

Tools share the existing registry/gateway/plugin contracts and canonical editing boundary. Raw JSON/file editing behind the gateway or topic-specific source generation is not the acceptance path. Rendering may delegate to the existing Remotion runtime behind an adapter; it need not introduce the P1.2 worker service early.

## Gate R — Minimum local reliability

- [ ] Concurrent identical idempotent calls cause one tested project mutation; same key with different input is rejected both while pending and after completion. Record ownership and concurrency reservations are released correctly on failures.
- [ ] Persisted execution evidence survives restart. Interrupted or uncertain work is explicit and cannot masquerade as success; document replay/recovery boundaries without claiming distributed exactly-once execution.
- [ ] Test cancellation before execution, during storage admission and during a running call, plus timeout behavior. Host execution/policy failures produce inspectable diagnostics.
- [ ] In-use asset removal is rejected or performs an explicit valid cascade. Project/reference commit failures recover conservatively; assets needed by another project or retained snapshot remain available after GC and restore.
- [ ] Reconciliation handles changed content under the same asset ID and URI/hash conflicts. Unsupported animation/capabilities are diagnosed rather than silently changed.
- [ ] The host uses an explicit permission allow-list and bounded invocation limits. Destructive/high-cost operations require approval or are unavailable in this first workflow.

## Gate C — Actual creation, editing and restoration

- [ ] From an empty project, discover manifests and use the proposed tools to build text, shapes and animation, commit a snapshot, render a preview and export a video. Verify project/schema/revision/Artifact integrity at each boundary.
- [ ] Produce two different-topic short fixtures (target 10–30 seconds each), for example CPU/cache data flow and a water-cycle diagram. Both use the same tool/renderer implementation and data-driven content; no new topic-specific TSX scene is added.
- [ ] Change one identified object's text/position and one animation property via tools. Assert the expected sampled values and meaningful pixel/frame changes; check unrelated project nodes/approved content remain unchanged.
- [ ] Save, restart the local host, restore and render again. Compare canonical data, asset hashes and declared frame tolerances; do not assume byte-identical MP4s across different rendering environments.
- [ ] Test a failing mutation, a safe retry and a plugin version switch within the integrated path, including a failed upgrade that preserves the previous usable implementation.

## Gate Q — Technical and visual quality

- [ ] Automated output checks cover streams, expected dimensions/FPS/duration and integrity. For fixtures with narration, verify audio presence and record an audio/caption synchronization review.
- [ ] Sample start/middle/end and significant keyframes. Record review of approved text, legibility, clipping, accidental overlap and motion timing. Automated checks and human visual review are reported separately.
- [ ] Render evidence identifies project revision/snapshot hash, exact tool/plugin choices, adapter version, render profile, output hashes and diagnostics. Preserve before/after previews for the targeted edit.

These gates establish a usable initial 2D subset, not advanced 3D, physics simulation or final long-form production quality.

## Gate X — Extension and catalogue scale

- [ ] Register/discover/page/filter/resolve 300 synthetic manifests across multiple namespaces and versions. Exercise conflicts, deprecated entries and incompatible capabilities. Record timings and environment before setting performance targets.
- [ ] Add one executable test plugin/tool through public contracts without modifying registry, gateway or agent orchestration core.
- [ ] Report counts separately: executable built-ins, catalogue-only fixtures and synthetic scale entries. The 300 entries do not represent 300 finished creative tools.

## Gate A — Real AI invocation trial

- [ ] Expose discovery and invocation through a thin local host interface usable by an AI client, not direct source-code mutation.
- [ ] Record one real AI trial creating and revising a short fixture using discovered schemas and diagnostics. Capture the model/provider, approved brief, tool catalogue, calls, revisions, outputs and any human intervention.
- [ ] Keep the deterministic regression scenario alongside this trial. Separate agent decisions from renderer execution; a broad autonomous preview-analysis system is P1.4.

## Closure evidence

Keep every box open until its evidence exists. The final acceptance report records one commit SHA, CI run, gate/test mapping, tool/capability inventory, two project fixtures and previews/exports, mutation/restore comparisons, failure cases, visual-review notes, AI trial trace and deployment limitations.

A passing CI run can close the existing checks it actually executes, not unimplemented gates. New scope must either serve these gates or be assigned to a later phase in [PLAN.md](PLAN.md).
