## Local protocol

Run `npm run --silent host:stdio -- --config /path/to/trusted-config.json`. The application supplies a trusted JSON config with `schemaVersion: "1.0.0"`, workspace `directory`, a new `traceFile`, and a project-bound `grant`. Paths resolve relative to that config. The [recorded config](ai-trials/cache-hit-2026-11-17/launch-config.json) is an example of explicit permissions and 16 allowed tool IDs. Copy it into a fresh temporary directory to experiment; running it next to the original transcript intentionally fails rather than overwriting evidence.

```bash
trial_dir=$(mktemp -d)
cp docs/ai-trials/cache-hit-2026-11-17/launch-config.json "$trial_dir/config.json"
npm run --silent host:stdio -- --config "$trial_dir/config.json" <<'JSONL'
{"id":"tools","method":"discover","params":{"limit":30}}
{"id":"create","method":"invoke","params":{"toolId":"project.create","toolVersion":"1.0.0","input":{"name":"New draft","episodeId":"approved-brief"},"runId":"local-demo","callId":"create-1","idempotencyKey":"create-once"}}
{"id":"end","method":"close","params":{}}
JSONL
```

This is a local sequential process protocol, not an MCP/HTTP service, provider SDK or general planner. Stdout contains only JSON Lines; startup/shutdown errors go to stderr. A ready message identifies the protocol and project. Each request needs an `id`, `method` and object `params`; optional `note` holds a short decision summary.

| Method | Parameters / result |
| --- | --- |
| `discover` | Existing `ToolSearchQuery`; returns only allowed manifests |
| `manifest` | `{toolId}`; returns allowed manifest or null |
| `invoke` | Exact `toolId`, `toolVersion`, `input`, `runId`, `callId`, optional `idempotencyKey`; returns existing ToolResult |
| `close` | `{}`; stops admission, drains the host and acknowledges closure |

Outer `ok` describes transport dispatch; an invoked tool also has its own `result.ok` and diagnostics. Clients must check both. Plugin administration, paths, permissions and project selection are not accepted from request messages. Use unique execution call IDs; retry an uncertain mutation with its original input and idempotency key, not an unrelated reused call ID. The host's existing durable idempotency/permission/version rules remain authoritative.

Requests are newline-terminated and limited to 1 MiB by default (also the maximum). A partial final line is never executed. Malformed JSON gets an error and can be followed by another complete request; excessive bytes, invalid UTF-8 or truncated framing close the transport. Replies are capped at 10 MiB; the synced journal defaults to 64 MiB, with a configurable maximum of 128 MiB. These are transport limits, not process isolation or hard compute budgets.

Every request is journaled before dispatch; every response is journaled before transmission. The journal is created exclusively and cannot overwrite an existing file. If recording or output fails after admitting an invocation, its effect may already be persisted: the transport stops later calls and reports `outcomeUnknown` where possible. Consult execution evidence before retrying. EOF, explicit close, SIGINT and SIGTERM revoke/drain the bound host; there is no per-call cancellation RPC in this slice.

## Executable validation

```bash
npm run typecheck
npm test
npm run accept:ai-trial
npm run accept:creative-loop
```

The six transport tests cover real CLI framing/EOF, UTF-8 chunking, discovery, scoped grants, rejected authority injection, version mismatch, idempotency/reopen, malformed/truncated/oversized input, trace-write uncertainty, disconnected output and pre-aborted startup. No renderer is needed for those unit tests.

`accept:ai-trial` requires the Remotion browser, Noto CJK fonts and FFmpeg. It validates original file hashes, ordered request/response pairs, catalogue/version identities, snapshot integrity and scoped repair. It then launches the actual CLI against an empty temporary workspace and replays all 52 requests, preserving a separate transcript. It compares canonical project data after normalizing only project/revision audit timestamps, checks the same defect/recheck outcomes, verifies output receipts, fully decodes both original and replay MP4 pairs, and checks meaningful text/motion pixel changes plus unchanged title pixels. MP4 bytes are not required to match across environments.

CI runs this alongside the existing two-topic restore/plugin-switch regression and uploads `ai-trial-replay-evidence`, including on validation failure. `out/ai-trial/evidence.json` explicitly records `newModelCalls: 0`; a successful replay validates implementation stability, not a second AI trial. The original trial remains checked in under `docs/ai-trials/`.
