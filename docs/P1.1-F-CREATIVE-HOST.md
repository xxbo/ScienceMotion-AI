# P1.1-F — Creative Host Assembly

## Purpose

Provide one trusted local application composition for project-bound AI sessions. The host joins the existing filesystem workspace, Artifact lifecycle, persistent execution evidence, pinned plugins, Registry and Gateway. It does not replace the Project Graph, editorial package or renderer.

## Startup and ownership

Use `openCreativeHost({ directory, plugins, limits })` from trusted application code. The directory is application configuration, never tool input. One exclusive `host.lock` covers project, artifact, reference and execution data. Startup opens and recovers the workspace and execution ledger before activating the exact configured plugin versions or accepting sessions. Corrupt authoritative state fails closed.

## Session grants

The application calls `host.createSession()` with a project ID, explicit tool IDs and explicit permissions. Both default to empty. No wildcard permissions or wildcard tool grants are accepted. Each invocation carries tool ID/version, input, run/call identity and optional idempotency key; project identity is taken from the session, not from tool input.

Service operations check three independent declarations: session permission, plugin permission and tool permission. Destructive operations additionally require explicit session approval and a destructive tool declaration. High-cost tools require explicit high-cost approval. Host policy bounds input bytes, project bytes, artifact bytes, patch operation count, sessions, concurrent calls, per-tool concurrency, timeout and retry attempts.

## Built-in workspace tools

The `builtin.workspace` plugin provides:
- `project.create`, `project.inspect`
- `project.patch.apply`, `project.patch.remove` (separately approved)
- `project.snapshot.save`, `project.snapshot.inspect`, `project.snapshot.restore`
- `execution.list`

The scene/shot/animation editing operations use Patch protocol 1.3.0. The project format remains 1.1.0. The workspace tools are foundational project operations; they do not claim the P1.1-G graphics, animation authoring and rendering suite is complete.

## Artifact and snapshot boundary

Plugins receive scoped services, not raw stores or paths. Artifact uploads receive host-assigned provenance and are retained by invocation. Reads require project, snapshot or same-invocation ownership and verify bytes against SHA-256 metadata. Snapshot reads pin the snapshot's own artifact dependencies for the active tool run. GC and snapshot release are host maintenance operations.

## Shutdown

Host close immediately stops admission, shuts down Gateways, drains actual tool/service work, closes execution/workspace stores and releases the exclusive lock. Close is idempotent. A failed close remains visible as a failed host state; the lock is retained if persistent resources could not be closed safely.

## Verification

`creative-host.test.ts` covers grant isolation, exact tool versions, project binding, destructive approval, service capability expiry, async service draining, cancellation, timeout/drain, host close, artifact ownership/integrity, snapshot pinning and operation limits. `creative-host-integration.test.ts` exercises the production filesystem composition across restart, idempotent replay, plugin health failure, workspace lock, corruption recovery and snapshot/artifact GC protection.

Local tests are not a substitute for the full CI result. This host is a trusted in-process, single-writer local composition, not a third-party plugin sandbox, distributed transaction service or P1.1-G renderer.


### CI correction — Patch Schema strict array typing

After the self-contained keyframe reference fix, all 170 platform tests passed. The next CI step then failed because the Patch 1.2.0 conditional schema constrained `patches.items` without declaring `patches.type: array`, which Ajv strictTypes rejects. Added the missing array type. The validation script now compiles the Patch Schema independently in strict mode and rejects all external `$ref` dependencies, preventing both regressions.
