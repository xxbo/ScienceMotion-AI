# P1.1-G — Snapshot inspection I1

## Public contract

`inspect.snapshot({ snapshotId, frames? })` is a read-only built-in tool requiring `snapshot.read`. It consumes a retained snapshot owned by the session project and returns a typed `SnapshotInspectionReport` (schema 1.0.0). It does not invoke a renderer/vision model or encode video. The ordinary execution ledger still records the invocation.

The host validates the canonical document and ownership; the inspector verifies snapshot hash and project/revision identity. Reports contain snapshot/revision/project/sequence identities, inspector version, exact checked frames, grouped issues, per-frame element counts and coverage exclusions. Tool diagnostics carry node/track/scene IDs and affected frames where applicable.

`ok: true` means the tool completed, including when it found error-level issues. `outcome: no-issues-detected` applies only to the declared checks and frames. It is not a final-video correctness claim.

## Checks and limits

- Reuse model diagnostics for missing scenes, unsupported nodes/animation and invalid chart/path data.
- Warn if a scene has no projected elements with positive opacity and dimensions. These are visible candidates, not measured pixels.
- Check affine-transformed declared shape/chart rectangles for outside-frame, clipping and collapsed geometry. Offscreen motion may be intentional, so position findings are warnings. Text and arbitrary SVG path ink bounds are not inferred from their declared boxes.
- Inspect all frames for sequences up to 120 frames. Longer sequences sample scene boundaries, animation keys/neighbours and uniform probes, capped at 120 frames. Explicit requests accept 1–120 unique in-range integers and are sorted without mutating the caller's array.
- Disclose omitted automatic candidates and unsampled frames. Sampled checks do not prove looping animation or between-sample extrema safe.
- Cap distinct issues at 200, disclose truncation/omitted occurrences, and reject requests exceeding the 250,000 estimated-work budget. Explicit frames can narrow expensive checks.
- The current renderer only supports the first sequence; multi-sequence documents receive a warning and require review.

Browser/font layout, text overflow, path extents, occlusion, final pixels, asset-byte integrity, audio, scientific correctness and presentation quality are explicitly unchecked. Document integrity does not imply a fresh read of every asset's bytes.

## Regression evidence

`snapshot-inspection.test.ts` covers immutable reports, intermediate-frame motion, nested/rotated/collapsed geometry, diagnostic identities, malformed creative data, sampling, integrity/input/work limits and truncation.

`snapshot-inspection-host.test.ts` exercises the real Registry/Gateway/filesystem host, typed output validation, grants, cross-project denial, service-level plugin/tool authorization and restart equivalence. Injected rendering adapters throw if invoked.

Run `npm run inspect:snapshot-smoke`: public tools create an animated signal with valid endpoints but an offscreen middle; inspection identifies the affected node/frames; tools repair keyframes; new inspection clears the issue; old-snapshot reports and post-restart reports remain stable. It writes `out/snapshot-inspection-evidence.json` with source commit (in CI), reports, timings and zero render/vision calls. CI runs this before browser setup and uploads the evidence with video artifacts.

This deterministic scenario does not close real-AI, complete two-topic restore or human visual-review gates. [PLAN](PLAN.md) defines I2 browser measurements and subsequent acceptance work.
