# I2: Browser layout inspection

`inspect.layout` adds actual browser measurements to the I1 model checks. It is a read-only tool bound to the caller's snapshot and requires only `snapshot.read`:

```json
{"snapshotId":"layout-before","frames":[0,30,59,60,90,119]}
```

Omitting `frames` samples shot/animation boundaries and uniform probes. At most 12 frames are measured; coverage names exact frames and omitted candidates. A successful tool call means measurement ran, not that the whole video is visually correct.

## Production path

Host ownership/schema/hash validation → bounded frame selection → the existing Remotion `ProjectGraph` composition → `document.fonts.ready` and a layout frame → DOM element/Range measurements → a nonvisual Remotion Artifact → typed JSON report.

The adapter calls the public `renderFrames` API with `imageFormat: "none"`, `outputDir: null`, one browser tab and the requested frame list. It does not take screenshots or encode video. The same composition, data projection, fonts, transforms and CSS are used for normal PNG/MP4 exports. An inspection-only probe emits metadata and does not change the drawing surface's styles.

The host verifies project, scene, frame, viewport dimensions, font readiness, node identities/types, declared sizes and opacity against the requested model. Missing or mismatched evidence fails the call rather than returning a clean report. I1 remains available without starting a browser. A custom renderer that lacks layout measurement returns `HOST_LAYOUT_UNAVAILABLE`.

## What the report means

`SnapshotLayoutInspectionReport` / `schemas/snapshot-layout-inspection.schema.json` version 1.0.0 includes snapshot/revision identities, coverage, browser metadata, per-frame/node measurements and bounded issues.

| Evidence | Interpretation |
| --- | --- |
| `declared` | The project's intended width and height, in untransformed layout units |
| `elementBounds` | Actual transformed DOM element bounding box, in viewport coordinates |
| `contentBounds`, `lineBoxes` | Text Range line rectangles, not glyph ink; other nodes use their element box |
| `text.layoutWidth/Height`, `overflowX/Y` | Browser scroll dimensions versus declared width/height, before transforms |
| `viewportOverflow` | Measured content-box distance outside each canvas edge |
| `firstFamilyStatus`, `fontProbeWidths` | Heuristic comparison against three generic font families; not exact font identity |
| `cost` | Measured elapsed time and browser-frame count; image encodes and visual-model calls are zero |

Text uses `minHeight` in the existing renderer: when a paragraph needs more height, the element grows. `LAYOUT_TEXT_OVERFLOW` reports that it exceeded the allocated box; it does not falsely claim the renderer clipped the text. `LAYOUT_VIEWPORT_OVERFLOW` and `LAYOUT_FONT_FALLBACK_LIKELY` are also warnings requiring intent-aware edits. Fully transparent nodes are measured but do not receive visible-overflow/font warnings.

Font metrics can also produce small overhangs without visible clipping. For example, inspecting four frames of the existing CPU-cache sample locally reported six 2–4 pixel height reminders. These are measurements to review, not proof that those titles look wrong. Do not treat any warning count or a warning-free report as a visual-quality score.

Rotated or scaled text retains browser-measured axis-aligned line/element boxes. Font comparisons only test the first named family. A font may exist and still fall back for individual Chinese/emoji glyphs. Browser UA, device pixel ratio and probe widths are reported; they do not establish a persistent font-environment identity or authorize cross-session cache reuse.

Not measured: exact glyph fonts/ink, SVG path extents, internal chart text layout, overlap/occlusion, final pixels, audio, scientific correctness, presentation quality or unselected frames. A warning-free report is restricted to these checks and selected frames. Adaptive motion refinement and cross-session caching are deferred.

## Limits and lifecycle

- Up to 12 unique in-range frames, 4096 pixels per canvas dimension, 200 projected nodes and 20,000 text characters per frame, 1,200 node-frame measurements, and 1,000,000 estimated projection operations.
- 200 reported issues; additional occurrences are counted explicitly. Each text record stores at most 32 line boxes while preserving full line count/content bounds and a truncation flag.
- The existing 30-second tool limit applies; render cancellation is connected to tool/session cancellation. Host close drains actual work. Snapshot/project state is not changed and no rendered artifact is published by this tool.
- Resource checks are trusted in-process safeguards, not worker isolation or enforceable OS quotas.

## Regression evidence

Run `npm run inspect:layout-smoke` after installing the Remotion browser, Noto CJK fonts and FFmpeg. CI runs it and uploads `out/layout-inspection-evidence.json`, `out/layout-before.png` and `out/layout-after.png`.

The fixture starts with a narrow paragraph, a text node leaving the canvas at frame 30 despite valid endpoints, a nonexistent font and a separate second scene. I1 reports no model issues for those text cases. I2 identifies each defect and the second scene's actual nodes. Public patch/keyframe tools repair them; I2 rechecks the old/new snapshots, preserves unrelated state and reproduces measurements after a host/browser restart.

Two separate normal PNG renders verify that measured line rectangles contain actual text ink and that fixing wrapping visibly reduces the paragraph's height. These are regression evidence, not screenshots used by the inspection algorithm. Existing chart and video pixel/media regressions remain in CI. Unit/host checks cover mismatched evidence, budgets, grants, ownership, renderer capability and cancellation.

This delivers bounded I2 measurement, not P1.1 completion. Next: integrated two-topic creation, targeted revisions, export and restore; then extension/real-AI acceptance and the deferred human effect review.
