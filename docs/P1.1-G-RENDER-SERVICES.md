# P1.1-G — Snapshot Render Services

## Public tool surface

- render.preview({ snapshotId, frame, sceneId? }) produces a PNG Artifact for one frame.
- render.video({ snapshotId, startFrame, durationFrames, sceneId? }) produces an H.264 MP4 Artifact for a bounded range (maximum 900 frames / 30 seconds at 30 FPS).

Both tools use the existing Plugin → Registry → Gateway → invocation-scoped CreativeServices path. The AI supplies a snapshot identity and frame parameters only; it cannot supply a filesystem path, output path, renderer executable or entrypoint.

## Trust and consistency boundaries

1. The host verifies the snapshot exists and belongs to the session project.
2. It validates the immutable document against Project Schema and verifies its canonical SHA-256 content hash.
3. It validates frame/range bounds against the snapshot's first sequence.
4. It renders a cloned snapshot document through the trusted ProjectGraphRenderer.
5. It checks output type, extension, byte length and renderer identity/version.
6. It stores bytes in the content-addressed ArtifactStore and attaches render evidence metadata: snapshot ID/hash, source revision, frame/range, dimensions/FPS and renderer identity/version.
7. The tool returns the Artifact reference. Gateway output validation verifies the content hash/URI and retains the Artifact under the current project/run/call.

Required permissions are snapshot.read and artifact.write, intersected across session, plugin and tool. Foreign-project snapshots, invalid hashes, out-of-range requests and oversized outputs fail before a successful Artifact is returned.

## Default renderer

RemotionProjectGraphRenderer uses the Remotion bundler and renderer APIs. It renders still PNG previews and H.264 MP4 ranges using the generic ProjectGraph composition. Composition metadata is derived from the supplied ProjectDocument sequence, so render duration, FPS and dimensions come from the immutable snapshot rather than the demo fixture.

The renderer can be replaced only by trusted application configuration, primarily for deterministic tests. Tool inputs cannot choose an implementation.

## Current boundary

The service is synchronous and local, with a 900-frame cap and the host's configured execution timeout/artifact byte limits. Persistent job progress, resumable rendering and worker isolation are deferred to P1.2. Multi-sequence orchestration, transitions, audio/captions and visual review remain later creative-loop work.

## CI verification

The workflow runs a production-host smoke scenario: create/edit a project through tools, save a snapshot, render a PNG preview and MP4 video through render.preview / render.video, then validate PNG signature and MP4 streams/dimensions/FPS/duration with ffprobe.
