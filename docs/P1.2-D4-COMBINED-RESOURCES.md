# P1.2-D4 — Combined render resource acceptance

One Creative Host runs two Linux workers at a time with a one-job waiting queue. Every job has a 2,500 millicore CPU bandwidth limit, a 22-second cumulative CPU budget, a 1,536 MiB memory ceiling and a 128 MiB temporary filesystem. The Ubuntu 24.04 fixture provisions two ext4 loop volumes and delegates the CPU and memory controllers to the ordinary runner user. Each worker gets its own cgroup and an exclusive volume lease. [CPU and memory configuration](P1.2-D2-CPU-MEMORY.md) · [Temporary disk configuration](P1.2-D3-TEMPORARY-DISK.md).

| Workload | Kernel evidence | Durable diagnostic |
| --- | --- | --- |
| Detached CPU load | CPU bandwidth throttling and aggregate usage at or above the cumulative budget | `RENDER_WORKER_CPU_TIME_LIMIT` |
| Detached memory allocator | Cgroup OOM events and kills | `RENDER_WORKER_MEMORY_LIMIT` |
| Detached temporary-file writer | An actual `ENOSPC` from writing or syncing within the assigned volume | `RENDER_WORKER_TEMPORARY_LIMIT` |

Each round captures the pressure process and a production video worker in separate cgroups and volumes. A fixture barrier holds the video after real frame progress with Chromium and FFmpeg live. The third job waits until the failing worker's children, cgroup and working directory are gone. It then leases the released volume while the original video worker still owns its volume. The same video worker renders additional frames after the barrier is released.

Each round verifies a 60-frame, two-second H.264 MP4 from the surviving worker and a 640 × 360 PNG from the queued worker. Both outputs have verified bytes, resource receipts and job retention. Failed records have their own diagnostic and no output receipt. The acceptance checks reclaimed blocks and inodes on both volumes, reaped processes, empty temporary directories and exact job records after host reopening.

With dependencies and the Remotion browser installed on Ubuntu 24.04, the same fixture can run through the CI helper. CI uploads the six media files and `evidence.json` as `render-worker-combined-evidence`.
