# P1.2-E1 — Render performance baseline

The baseline compares `RemotionProjectGraphRenderer` with `LocalRenderWorker` on the same immutable water-cycle snapshot, production Remotion entry point and 1920 × 1080 profile at 30 fps. The timed boundary is the snapshot renderer call. Workspace writes and artifact publication have their own acceptance checks. [Fixture](../examples/project-graph-demo.props.json) · [Worker lifecycle](P1.2-WORKERS.md).

Each pair runs the two modes sequentially and alternates which mode runs first. Each mode starts a fresh Node process, a private temporary directory and a private Remotion workspace with an empty bundler disk cache. Installed dependencies and the preinstalled browser are shared. All subsequent calls in that sample use the same renderer instance and workspace. The OS can retain cached pages between samples.

| Call | Workload |
| --- | --- |
| Cold preview | Render frame 45 with the fresh workspace |
| Repeat preview | Render frame 45 again in that workspace |
| Video | Encode frames 0–29 to H.264 MP4 |
| Layout | Measure frames 0, 45 and 90 without encoding media |
| Cancel video | Request frames 0–179 and abort after frame progress with a live Chromium descendant |
| Recovery preview | Render frame 45 after the observed cancellation processes are reaped |

The benchmark verifies preview bytes, decoded video frame content and layout measurements across both modes and repetitions. It checks media dimensions and the video frame count, cancellation rejection, process reaping, successful recovery and snapshot integrity. CI checks correctness and publishes raw samples, medians and observed ranges.

## Measurement boundaries

| Measure | Boundary |
| --- | --- |
| Host startup | Launch to the supervisor observing that the renderer process is ready |
| Startup, bundle and selection | Call start → first bundling progress → first selecting progress → first rendering progress |
| Render to settlement | Rendering progress to the settled renderer promise, including encoding, result handling and call cleanup |
| Cancellation | Abort to rejection and abort to confirmation that the observed processes have been reaped |
| Shutdown and reclamation | Supervisor shutdown signal file to a fully reaped process tree, then deletion of the isolated temporary and cache directories |
| CPU | Linux child user and system time for the entire sample, including reaped descendants |
| Memory | Largest sampled sum of process RSS across the owned tree. Shared mappings contribute to each resident set. |
| Disk | Peak allocated blocks sampled under the private temporary directory and under the workspace cache. The report includes the retained size of both at shutdown. |

The supervisor targets a 100 ms sampling interval. Use the memory and disk values as observed peaks. The raw report records the checkout, OS and kernel, CPU affinity, active cgroup settings, installed renderer versions, browser and font selection.

## Repeat the baseline

```sh
npm install
npx remotion browser ensure
npm run bench:render -- --samples 3
```

The Linux benchmark writes `out/render-performance/baseline.json` and `out/render-performance/summary.md`. The dedicated Ubuntu 24.04 job uploads both in `render-performance-baseline`. Use the same fixture and workload order for the E2 comparison. [Benchmark](../scripts/render-performance-baseline.py) · [CI workflow](../.github/workflows/video-engine.yml).
