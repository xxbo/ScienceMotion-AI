# P1.3 — Creative tools

Last updated 2026-11-23

Extend the public Project Graph tools so an agent can use media, edit a timeline, animate visuals, and export a short with narration and captions from an immutable snapshot. [Development plan](PLAN.md).

| Step | Status | Deliverable |
| --- | --- | --- |
| A | Implemented | Import an approved PNG, place it in a scene, replace it, and render both snapshots after reopening. |
| B | Implemented | Move, reorder and trim shots and place PNG clips. Verify the cut and frame ranges in previews and exported media. |
| C | Implemented | Edit existing geometry, SVG paths and chart data and styles. Verify the affected pixels and restore the older snapshot. |
| D | Implemented | Insert, update, retime and remove keyframes, and add an adjacent-shot crossfade. Verify easing, step and transition frames. |
| E | Implemented | Place approved WAV narration and timed captions. Verify the AAC audio, clip timing and burned-in caption boundaries in exported MP4s. |

## A — Approved PNG imports

Set `assetImports` in `openCreativeHost` or in the trusted stdio launch configuration. Each entry authorizes one source ID in one project. Stdio paths resolve relative to the launch configuration. The source ID is supplied with the tool invocation.

```json
{
  "assetImports": [
    {
      "projectId": "demo",
      "sourceId": "approved-diagram",
      "path": "approved/diagram.png",
      "license": "CC BY 4.0",
      "attribution": "Example author"
    }
  ]
}
```

1. Grant `assets.import` and the `project.read`, `project.write` and `artifact.write` permissions. Import with `{"sourceId":"approved-diagram","assetId":"diagram"}`. The result includes the asset and its Artifact hash. Use `replace: true` with an existing image asset ID to create a new project revision using the selected source.
2. Grant `graphics.2d.image.create` and project read/write. Supply `sceneId`, `nodeId`, `assetId`, `x`, `y`, `width` and `height`. The PNG fills the specified rectangle and follows the node's transform and opacity.
3. Save a snapshot and run `render.preview` or `render.video`. Foreground and background renders resolve retained bytes from the requested snapshot. To preserve both versions, save a snapshot before and after replacing the asset.

An approved input is a regular local file containing a decodable static PNG. The importer limits encoded bytes to 4 MiB and the host's artifact limit, both dimensions to 4096, and pixels to 8,388,608. It validates the compressed data and returns a bounded diagnostic on a bad input. The host records the source ID, supplied licensing metadata and content identity with the project asset.

A render loads distinct PNGs referenced by supported image nodes and selected timeline tracks. It has an aggregate limit of 4 MiB and 8,388,608 pixels. Worker jobs carry the byte payload in the existing 12 MiB request file, which is copied onto the leased work volume when a disk budget is configured. The renderer verifies the snapshot's artifact hashes before producing image sources. The prepared Remotion bundle supplies the application code. Layout inspection measures the image placement box. [Asset consistency](P1.1-F-PROJECT-ASSETS.md) · [Prepared bundles](P1.2-E2-BUNDLE-REUSE.md).

## B — Timeline editing

Grant `timeline.edit` with project read/write. Read the project to get the latest revision and shot IDs, then submit `baseRevisionId` and an ordered `edits` array. The tool commits a single revision and returns the sequence duration, ordered shot and track IDs, and the shot and clip IDs touched by the batch.

| Operation | Fields beyond `op` | Effect |
| --- | --- | --- |
| `move-shot` | `shotId`, `startFrame` | Set the shot's timeline start. |
| `trim-shot` | `shotId`, `inFrame`, `durationFrames` | Set the source-scene start and the shot length at its current timeline start. |
| `reorder-shots` | `shotIds`, optional `startFrame` | Pack a permutation of every shot contiguously from `startFrame`, which defaults to 0. |
| `place-clip` | `trackId`, `clip` with `id`, `assetId`, `startFrame`, `durationFrames` | Place a project-owned PNG on a video track, creating the track if needed. Reuse a clip ID to move or update its placement. |

Edits use zero-based frame indices on the first sequence. Intervals include their start and exclude their end `[startFrame, startFrame + durationFrames)`. The sequence keeps its configured duration and frame rate. A gap shows the canvas background. Each shot covers the scene frames beginning at `inFrame`, which defaults to 0. A preview with an explicit `sceneId` uses the scene's source frames directly.

The final batch must keep each shot inside both the source scene and sequence and each clip inside the sequence. Shots may touch at a cut. Overlapping shots and overlapping clips on the same track reject the batch, as does a stale revision. PNG clips on separate video tracks can overlap. PNGs fill the canvas and blend using their alpha channel, with later tracks drawn over earlier tracks and the scene. These rules apply to `timeline.edit`. Legacy snapshots with shot overlaps retain their original precedence.

The edit uses [Timeline Patch 1.4.0](../schemas/project-timeline-patch.schema.json) through the scoped host. The Project Graph stores shot source offsets and sequence track membership, with asset dependencies retained by snapshots.

## C — Edit existing 2D graphics

Grant `graphics.2d.edit` with project read/write. Submit the latest `baseRevisionId` and an `edits` array of `{kind, nodeId, changes}`. The tool applies the entries in order and returns one new revision and the changed node IDs. Each entry updates only the supplied geometry fields, preserving node IDs, transforms, hierarchy, animation tracks, and other component data. Invalid entries and stale revisions reject the batch before publication.

| Kind | Editable fields |
| --- | --- |
| `shape` | `primitive` (rect, circle, ellipse or line), `width`, `height`, `radius`, `fill`, `stroke`, `strokeWidth` |
| `path` | `pathData`, `fillRule` (nonzero or evenodd), `width`, `height`, `fill`, `stroke`, `strokeWidth` |
| `chart` | `chartType` (bar or line), `data`, `width`, `height`, `fill`, `stroke` (axes and grid), `strokeWidth` (line series), `labelColor`, `fontSize` |

Charts take an ordered array of 2–24 `{label, value}` points with finite values and nonblank labels of up to 48 characters. Supplying `data` replaces the series. Path data takes complete SVG draw commands with finite coordinates, up to 20,000 characters. Paint accepts 3-, 4-, 6- or 8-digit hex colors and the renderer's named colors, including `transparent`, `black`, `white`, `red`, `green`, `blue`, `orange`, `yellow`, `purple`, `gray`, `grey` and `cyan`.

The editor emits a revision-guarded Project Patch 1.3.0 batch and uses the existing geometry components for all three kinds. Save a snapshot before editing if you want to render or restore that revision later.

## D — Keyframes and crossfades

Grant `animation.keyframes.edit` with project read/write. Submit the current `baseRevisionId` and ordered `edits`. Each entry uses a `trackId` and an operation. The batch creates one revision and returns the edited track IDs.

| Operation | Fields beyond `op` and `trackId` | Effect |
| --- | --- | --- |
| `insert` | `keyframe` with `frame`, `value` and optional `interpolation` and `easing` | Insert a key at a free source frame. |
| `update` | Current `frame` and `changes` | Change the supplied fields. Set `changes.frame` to retime the key or `changes.easing` to `null` to clear its easing. |
| `remove` | `frame` | Remove a key. Each edited track must have at least one key at the end of the batch. |

Keys are zero-based scene source frames. The source duration may serve as a final interpolation anchor. The destination key controls the segment leading into it. Linear interpolation defaults to linear easing. Bezier interpolation uses the supplied CSS timing curve. Step holds the previous value and switches at the destination frame. The available timings are `linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out`, and `cubic-bezier(x1,y1,x2,y2)` with finite controls and both x controls in [0, 1]. For step, omit easing or use `linear`. The existing renderer clamps composed opacity to [0, 1]. Frame collisions, invalid curves, source bounds and stale revisions reject the batch. Use `animation.keyframes.set` to create or replace an entire track.

Add a dissolve through `timeline.edit` with `op: "set-transition"`, `fromShotId`, `toShotId`, and `transition: {type: "crossfade", durationFrames}`. The shots must share a cut in the first sequence. The duration is at least two frames and fits inside the incoming shot. At the cut, the outgoing shot's last visible source frame is held. The opacity of the incoming scene ramps linearly from 0 at the cut to 1 on the last transition frame, while its source animation advances normally. Timeline PNG clips compose above the dissolve. The effect uses the existing sequence frames and timing.

Pass `transition: null` with the same shot pair to clear a dissolve. A later timeline edit must keep each configured cut valid or clear it in the same batch. An explicit `sceneId` preview selects the source scene at its local frame. Automatic inspection includes transition boundary and midpoint candidates, and browser layout measures the selected incoming scene during the dissolve.

## E — Narration and timed captions

Add `mediaType: "audio/wav"` to the narration source in the trusted `assetImports` configuration. Grant the existing `assets.import` tool and import the approved `sourceId` with an `assetId` and `mediaType: "audio/wav"`. The importer accepts 16-bit PCM WAV in one or two channels at 8–96 kHz and limits the file to 4 MiB and the host's artifact limit. It records the sample count, sample rate, channel count and content hash with the project asset. Use `replace: true` to update an audio asset in a new revision that still fits the current placements.

Add narration and captions to one revisioned `timeline.edit` batch. Times are zero-based frames on the first sequence, with an inclusive start and exclusive end.

| Operation | Fields | Effect |
| --- | --- | --- |
| `place-clip` | `trackId`, `clip: {id, assetId, startFrame, durationFrames, inFrame?, gain?}` | Place a WAV asset on an audio track. `inFrame` defaults to 0 and measures source time in sequence frames. `gain` is a linear multiplier from 0 to 2 and defaults to 1. Reuse the clip ID to move, trim or adjust its gain. |
| `set-caption` | `captionId`, `caption: {text, startFrame, durationFrames}` or `null` | Add, edit or clear a caption by ID. Text is plain text of up to 256 characters. |

Narration placements must fit both the WAV and the sequence. The narration intervals share one non-overlapping lane across audio tracks, and caption cues share a separate non-overlapping lane. Preview and video render captions at the bottom center above visual tracks, including shots with a crossfade. A `sceneId` override selects the source scene directly.

Save a snapshot and run `render.video` on the required frame range to export H.264 MP4 with AAC wherever the range uses audible narration. The renderer uses retained WAV bytes from the snapshot. It loads only audio clips intersecting the requested range and permits up to 4 MiB of distinct WAV inputs per render. Worker jobs also use the existing 12 MiB request limit. Captions are burned into the video. Their displayed timing comes from the supplied frame intervals.

## F — Integrated inspection and repair

Grant `inspect.timeline` with `snapshot.read`. Supply `snapshotId` and optionally `range: {startFrame, durationFrames}`. The [timeline report](../schemas/timeline-inspection.schema.json) binds the first sequence, frame rate, project revision and snapshot hash. It reports declared shot, crossfade, PNG, narration and caption intervals in `[startFrame, endFrame)` order. Requested ranges clip intervals and advance the source-frame origin for shots and narration. Use a narrower range if the request intersects more than 2,000 intervals.

Enable `requireNarrationForCaptions: true` for shorts that require each caption to follow narration. The report names each affected caption and the exact frame ranges outside declared positive-gain audio clips. This check uses clip placement and gain. Speech alignment and waveform checks require media validation.

The integrated scenario creates an eight-second Mandarin short about CPU cache with a PNG overlay, a crossfade, motion, a chart, narration and a timed caption. `inspect.snapshot` identifies an animated marker outside the frame, `inspect.layout` measures a clipped chart, and `inspect.timeline` flags the caption's early and late spans. The scenario uses the reported IDs to repair each issue through the public editing tools and reruns the three inspections on the new snapshot.

The scenario decodes all 80 frames and checks the transition, overlay and caption timing, plus the exported narration against the retained showcase source. It removes the original PNG and WAV files, reopens the workspace, restores the saved snapshots and exports the repaired video using an independent worker. The recovered preview hash and decoded video and audio hashes match the repaired export. CI publishes both MP4s, before/after reports, previews and the tool execution trace as `integrated-creative-evidence`.

## Verification and delivery

```sh
npm run accept:png-assets
npm run accept:timeline
npm run accept:graphics-edit
npm run accept:animation
npm run accept:narration
npm run accept:p1-3
```

The PNG scenario uses synthetic red and blue images to check placement in previews and all decoded frames of short MP4s. It removes the approved source files and reopens the workspace with independent workers. Both saved versions render again, and the preview hashes match the foreground path. It also verifies cross-project denial, corrupt artifact rejection and recovery. CI publishes outputs and `evidence.json` as `png-asset-evidence`. The temporary-disk acceptance additionally verifies image bytes and the prepared bundle on a real ext4 lease, checks rendered pixels, and verifies reclamation.

The timeline scenario rearranges two shots, trims into an animated scene and places PNG clips on two tracks. It probes PNG previews at the cut and gap boundaries, verifies a three-frame MP4 starting at frame 8, and decodes the reopened worker's 20-frame export at 25 fps (0.80 seconds). It checks both sides of the cut at frame 9, source-frame motion, clip blending and empty frames. The original snapshot's preview retains its hash after reopening. CI publishes renders and decoded pixel evidence as `timeline-evidence`.

The graphics scenario turns a rectangle into a larger ellipse, edits a path to cut a hole and change its stroke, and changes bar heights and chart colors. It compares pixels in the three regions and verifies every surrounding pixel against the original PNG. After reopening, it restores the original snapshot as an audited revision with the same preview hash and checks the edited snapshot's MP4 by decoding all eight frames. CI publishes previews, video and `evidence.json` as `graphics-edit-evidence`.

The animation scenario checks a retimed ease-in segment and exact step boundaries in a trimmed shot. It verifies a five-frame dissolve from frame 16 through 20, an incoming animated marker, and a PNG clip above the composite. The original cut preview retains its hash across reopening. The worker's 32-frame MP4 is decoded at 25 fps and checked frame by frame. CI publishes the previews, MP4 and pixel report as `animation-evidence`.

The narration scenario extracts the opening Mandarin line from the retained showcase and uses calibrated tones to measure source trim, gain and silence. It decodes an eight-second MP4 and a subrange export, checks AAC and the speech waveform, and verifies caption presence on every frame and the cue switch on frame 7. It removes the original WAVs before reopening and exporting through a worker. CI publishes MP4s, previews and `evidence.json` as `narration-evidence`. [Showcase source](showcase/README.md).
