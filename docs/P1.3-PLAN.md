## A — Approved PNG imports

Set `assetImports` in `openCreativeHost` or in the trusted stdio launch configuration. Each entry authorizes one source ID in one project. Stdio paths resolve relative to the launch configuration. The source ID is supplied with the tool invocation.

```json
{
  "assetImports": [
    {
      "projectId": "demo",
      "sourceId": "approved-diagram",
      "path": "approved/diagram.png",
      "license": "CC BY 4.0",
      "attribution": "Example author"
    }
  ]
}
```

1. Grant `assets.import` and the `project.read`, `project.write` and `artifact.write` permissions. Import with `{"sourceId":"approved-diagram","assetId":"diagram"}`. The result includes the asset and its Artifact hash. Use `replace: true` with an existing image asset ID to create a new project revision using the selected source.
2. Grant `graphics.2d.image.create` and project read/write. Supply `sceneId`, `nodeId`, `assetId`, `x`, `y`, `width` and `height`. The PNG fills the specified rectangle and follows the node's transform and opacity.
3. Save a snapshot and run `render.preview` or `render.video`. Foreground and background renders resolve retained bytes from the requested snapshot. To preserve both versions, save a snapshot before and after replacing the asset.

An approved input is a regular local file containing a decodable static PNG. The importer limits encoded bytes to 4 MiB and the host's artifact limit, both dimensions to 4096, and pixels to 8,388,608. It validates the compressed data and returns a bounded diagnostic on a bad input. The host records the source ID, supplied licensing metadata and content identity with the project asset.

A render loads distinct PNGs referenced by supported image nodes. It has an aggregate limit of 4 MiB and 8,388,608 pixels. Worker jobs carry the byte payload in the existing 12 MiB request file, which is copied onto the leased work volume when a disk budget is configured. The renderer verifies the snapshot's artifact hashes before producing image sources. The prepared Remotion bundle supplies the application code. Layout inspection measures the image placement box. ## Verification and delivery

```sh
npm run accept:png-assets
```

The scenario uses synthetic red and blue PNGs to check placement in previews and all decoded frames of short MP4s. It removes the approved source files and reopens the workspace with independent workers. Both saved versions render again, and the preview hashes match the foreground path. It also verifies cross-project denial, corrupt artifact rejection and recovery. CI publishes outputs and `evidence.json` as `png-asset-evidence`. The temporary-disk acceptance additionally verifies image bytes and the prepared bundle on a real ext4 lease, checks rendered pixels, and verifies reclamation.

Each increment requires full PR CI and verification of the exact main push. Human presentation review belongs to the final acceptance workstream. [Delivery agreement](PLAN.md).
