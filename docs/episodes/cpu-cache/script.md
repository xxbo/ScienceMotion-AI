# 第一集脚本：CPU 为什么需要缓存？

- 语言：简体中文
- 目标时长：约 30 秒（当前工程动画样片）
- 画幅：16:9，1920×1080，30 FPS
- 版本说明：本稿为镜头旁白草案；当前 CI 样片使用屏幕字幕，尚未合成真人感 TTS 配音。

## 镜头 1（0–4 秒）：问题

CPU 很快，内存为什么跟不上？处理器需要数据，等待数据却可能浪费大量计算时间。

## 镜头 2（4–8 秒）：等待

当数据供应跟不上执行速度，处理器就可能停下来等待。算得再快，也要等数据送到。

## 镜头 3（8–13 秒）：层级

于是，CPU 使用多级缓存：L1、L2、L3。越靠近核心通常越快、容量越小；越往下，容量越大。具体设计因处理器而异。

## 镜头 4（13–18 秒）：命中

如果数据已经在缓存中，这次访问就是缓存命中，数据可以沿较短路径返回。

## 镜头 5（18–23 秒）：未命中

如果缓存没有目标数据，就会发生未命中，需要继续向更低层级查找，必要时访问主存，再把数据带回来。

## 镜头 6（23–27 秒）：局部性

缓存有效，还因为程序具有局部性：会重复访问近期数据，也常访问相邻数据。

## 镜头 7（27–30 秒）：总结

缓存通过分层存储和利用局部性，让数据更靠近计算单元，减少等待。

## 科学准确性审查

- 不给出固定的 L1/L2/L3 或 DRAM 延迟数字，避免把特定 CPU 的测量值误当成通用规律。
- 缓存层级、容量、共享关系和替换策略取决于具体微架构。
- 命中/未命中示意图是概念图，不代表所有处理器的真实访问路径。
- 时间局部性指近期访问的数据可能再次被访问；空间局部性指相邻地址可能很快被访问。
